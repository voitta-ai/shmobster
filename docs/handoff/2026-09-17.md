# Handoff, 2026-09-17

One long session: v0.8.0 -> v0.15.0, seven releases, the security re-audit
closed, and a credential scrub on the development machine that is **still
mid-flight**. Written because the session's own transcript is about to be
scrubbed, so anything living only in it would be lost.

`docs/HANDOFF.md` remains the standing plan. This is the dated record of what
happened and what the next session needs that the plan does not say.

## Why every session is being quit

`scrub.py` refuses to touch **live-writer files** unless `--outside-session` is
passed, and that flag is only honest with every agent process stopped. Three
kinds of file are involved:

- `~/.claude/history.jsonl`, which every session appends to;
- the `file-history` of any session in the process list;
- **each live session's own transcript** --
  `~/.claude/projects/<project>/<session-id>.jsonl`.

The dry run deferred six such files. One of them is this session's own
transcript, which is why this document exists: the scrub rewrites the record of
the conversation that produced it, so anything living only in the transcript
would be gone. Everything in here is written down somewhere durable -- a
release note, an issue, a commit, or a memory file -- rather than left to be
read back out of the session.

Rewriting a file a running process holds open is the reason for the refusal, not
politeness: the process may rewrite it again from its own buffer afterwards,
undoing the scrub and leaving the credential in place while the tool reports
success. That is the same class of silent failure the whole audit exists to
catch, so the scrub declines rather than racing.

52 peer sessions were alive on this machine when the plan was made, which makes
this a scheduling step rather than a command -- and the reason the final pass
has not run yet.

## Do this first

**The main pass is done. Two steps remain, and the second one is easy to
forget because it is the scrub's own leftovers.**

`scrub.py --apply` ran 2026-09-17 and completed:

    scrubbing 1014 spans in 52 files; deferred (live writer): 6
    verified: residual kill-listed spans in scrubbed files = 0

What is left:

    # 1. with EVERY Claude session quit -- the six deferred files
    cd ~/.cred-audit && python3 scrub.py --apply --outside-session

    # 2. the backups the scrub just made, which HOLD THE SECRETS IN PLAINTEXT
    python3 scrub.py --delete-backups

    # 3. the two hand items
    rm -f ~/.openclaw/identity/device.json ~/.cred-audit/probe.outcd

**Step 2 is not tidying.** `~/.cred-audit/scrub-backup` is mode 0700 and
contains verbatim copies of all 52 files *as they were before the scrub* --
every value the pass removed, in the clear, in one directory. The scrub says so
on its last line and it is right to: a rollback path is worth having until the
result has been checked, and after that it is a fresh instance of exactly the
problem the audit exists to remove. Do not leave it there.

## Open, with a view

- **#211** -- the learning self-check skipped a correction turn. Settled from
  the code: hypothesis 3 is **wrong** (`mark_thread` fires only on flag,
  propose, decline, so nothing marked the thread "considered"); hypothesis 1 is
  **right** (the bar names three shapes and "my earlier answer was wrong and I
  now know why" is none of them). The real cause is structural: **there is no
  end-of-turn self-check.** `flag_skill` is a tool called during composition, so
  the feature asks for a judgment about the turn's conclusion through a
  mechanism that runs before the conclusion exists. Fix: name the correction
  shape, tell it to judge the conclusion, and put the bar in the system prompt
  where it is in view while composing rather than only in a tool description.
  `flag_considered: <why not>` cannot capture the model's reason without asking
  every turn; the cheap substitute is recording that `flag_skill` was available
  and unused, with the turn's tool count.

## Corrections made during the session, kept because the reasoning matters

- **I said the live box ran v0.7.2.** It runs v0.8.0. The number came from the
  2026-09-13 triage and I repeated it through four sets of release notes without
  re-checking it.
- **I filed #186 on a premise that was false.** It claimed TMPDIR let a channel
  reach what #184 closed; #184's deny is a regex and was never anchored to the
  channel's tree, so TMPDIR was already covered. The investigation was still
  worth it -- it found the `cd` retargeting hole instead.
- **I called two credentials "already remediated" and they had moved.**
  `~/.claude/yolt.log` was clean because it had been **rotated**; the keys were
  in `yolt.log.old`, five megabytes of it, one directory listing away. A value
  leaves a file two ways, and I had checked only that it had left. `classify.py`
  now says *check rotations/backups before believing it is gone*.
- **My own positive control put credential shapes into this transcript.** They
  were synthetic, the PreToolUse hook flagged it correctly, and the scrubber
  later found them in this session's own file. Control shapes belong on stdin,
  not in argv.

than from memory, and handed to the `voitta:skillz` session to merge (lanes:

fixed, and the rule underneath all of it -- **in a pipeline whose last step
deletes things, "I could not read it" must never become "safe to remove."**

That rule turned up four separate times today in unrelated code: an unpriced
model call is not `$0`, a gate with no wordlist is not `clean`, a `gh api` whose
repo cannot be resolved is not allowed, and an unattributed cost is not one
vendor's.
