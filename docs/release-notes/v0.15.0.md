Three changes: a gate that was half-off, a tool for reading a pasted link, and a
receipt for an approval click. No new config key -- the sixth release running,
which is one of the four things 1.0.0 is waiting for.

## What an upgrade requires

Nothing mandatory. One thing worth doing, and one new capability to decide about.

**1. Give the pre-publish gate its wordlist (#204).**

`scripts/check-sensitive-terms.sh` used to print `check-sensitive-terms: clean`
on stdout whether or not it had a name wordlist, with the explanation on stderr
-- where the caller reading the result does not look. Measured on the
development machine: **every pre-commit run passed with the name half switched
off**, while a 34-term list sat one directory away under `~/.config/skillz/`.

The lookup now falls back to the shared path, and a run with no list anywhere
says so in the line you actually read:

    check-sensitive-terms: clean (STRUCTURAL ONLY -- no name wordlist, the
    client/employer/project name half did NOT run)

Exit stays 0, because structural-only is what CI legitimately does: a private
wordlist cannot live on a public runner. Set
`SHMOBSTER_SENSITIVE_TERMS_REQUIRED=1` where you want the absence to be fatal.

A wordlist is per **machine**, not per repo -- the names that must not be
published are the same whichever checkout you are standing in.

**2. Decide whether channels should read URLs (#62).**

`web_fetch` reads a page somebody pasted. It obeys the channel's existing
`allow_domains` through the same function the shell fetch uses, so a channel
with no list reaches nothing and **no new key is involved**. If you want a
channel reading links, its `allow_domains` is already the control.

Three things it does that a shell `curl` does not: it refuses a host that
resolves to loopback, link-local or private space (the metadata endpoint, the
router, anything on the box that believed it was unreachable); it reports
redirects instead of following them, because a redirect is a second fetch to a
host nobody checked; and what comes back is fenced and labelled as somebody
else's writing, so a page saying "ignore your instructions" is a page that says
that.

Stdlib only -- no Firecrawl, no dependency, no key.

**3. Approval clicks now have a receipt (#206).** Nothing to configure.

`:eyes:` the moment the click lands, then `:white_check_mark:` on approve or
`:no_entry_sign:` on deny when the result arrives. The card was already rewritten
to a claimed state before the work (#101) and that was not enough: a reaction is
the signal people are trained on in Slack, and a card rewrite is not. Denial is
not failure, so it gets its own mark rather than the one that reads as an error.

It needs `reactions:write`, which the app manifest already requests. Without the
scope the receipt is a no-op and nothing else changes.

## Known and open

- **#208** -- `gh` inside a channel is unauthenticated by construction: #112
  builds the child's environment from an allowlist and #116 denies
  `~/.config/gh/hosts.yml`, so there is no credential to find. Both are working
  as designed; what is wrong is that it is invisible, and gh's own error text
  recommends `gh auth login`, which cannot work from inside a sandboxed child.
  A channel that needs authenticated `gh` passes a token through its policy
  `env` or `env_passthrough`.
