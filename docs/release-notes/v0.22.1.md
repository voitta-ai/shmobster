Startup now says where the log is actually going. Warnings only; nothing else
changes.

## What an upgrade requires

Nothing. No new config key.

**Two boxes will see new warnings, and on both they will be true.**

## A 251 MB, world-readable log that #155 was supposed to prevent (#230)

The development box had `logs/shmobster.err.log` at 251 MB, mode 0644, still
growing. #155 exists to stop exactly that -- its own docstring names the same
failure at 185 MB -- and it did not, for two reasons that compound.

**`logging.path` was unset.** `handler()` then returns a plain `StreamHandler`
and the rotating 0600 log is never installed. The protection was opt-in and
silently off: correct, present, and not in effect. The same shape as #204 and
#229, which is three in this repo now.

**The supervisor's file exists either way**, and this is the half that matters.
launchd redirects stderr to `StandardErrorPath` whatever the config says, and
the crash that filled this one happens in `slack_app`'s `App()` constructor at
*import* -- before `main()` ever calls `setup()`. So setting `logging.path`
would not have prevented it. A crash-looping box writes the same traceback into
an unrotated file forever.

    logging: logging.path is unset, so the agent logs to stderr and whatever
      started it owns the file -- unrotated, at a mode this process did not
      choose. Set logging.path (see the example config) to get the rotating
      0600 log (#155)
    logging: stderr is a file with mode 0644 -- readable beyond its owner. It
      holds every command every channel asked for
    logging: stderr is a file of 251 MB and nothing here rotates it -- the
      supervisor redirected it (launchd's StandardErrorPath), so rotation is
      the supervisor's job (newsyslog.d) or the file needs truncating

### Found by asking what stderr is, not by reading the plist

The process does not know its own `StandardErrorPath`. It can `fstat` fd 2.
That covers launchd, `nohup` and `2>file` with no path guessing, and says
nothing at all when stderr is a tty or a pipe.

### Warnings only, deliberately

Nothing is truncated, chmod-ed or rotated by this release. The supervisor owns
that file, and a process quietly rewriting the mode of something it did not
create is a worse habit than the one being fixed. An existing oversized log is
a reset to do by hand:

    : > logs/shmobster.err.log        # truncate in place; launchd holds the fd
    chmod 600 logs/shmobster.err.log

...and then either set `logging.path` so the agent's own log is managed, or
hand the supervisor's file to `newsyslog.d`. Preferably both: they are
different files and only one of them is shmobster's.

## Why this is a patch

Nothing a channel can observe, no config key, no change to what runs or what
needs approving. Startup gains three warnings that are true on the boxes where
they fire.

## Checks

`selfcheck.py` check 56: unset `logging.path` warns; a pipe warns about nothing;
the live shape -- a 251 MB sparse file at 0644 on fd 2 -- produces both the mode
and the size warning; a small 0600 redirect target produces neither.
