Four changes, all from one afternoon of watching a channel try to ship, and all
about the same thing: who this agent is talking to, and what it is for.

## What an upgrade requires

Nothing mandatory. **One new config key, optional** -- `project_docs`, below.

## The agent reads the repo's own instructions (#259)

The expensive one. `seeds-of-doubt` documents, in committed files, that a
collaborator's branch is what deploys to their subdomain. Six weeks of UX work
sat on a feature branch instead, invisible; asked why, the agent read `git log`
for one branch, found nothing, and reported the work had never been written. It
existed one branch over, and the file saying so was in the tree the agent was
standing in.

That is the agent's job, not the collaborator's, and it is the arrangement this
whole deployment exists to support: one technical person sets up the workflow,
the deploys and the infrastructure, and the people in the channel are
specialists -- design, content, a domain the operator does not have. A designer
describing a screen should not have to know which branch makes it appear.

`CLAUDE.md`, `AGENTS.md`, `docs/CLAUDE.md` and `docs/AGENTS.md` are read when
present, plus anything a channel names in `project_docs`:

    "project_docs": ["docs/BRANCHING-STRATEGY.md"]

Read per turn, so a merged change takes effect without a restart -- and read
from the last **commit**, not the working copy. That is the safety argument
rather than a detail: `memory.py` refuses any prompt file under a writable
root, because the grant layer runs an in-tree write with no card, and the file
wanted here is inside the channel's tree by definition. An uncommitted edit --
what a turn can make silently, and in an unattended channel with no card --
steers nothing. A commit does, deliberately: it has an author and a diff.

Two defects the self-check caught before review: a channel with no `cwd` fell
through to the default and read THIS repo's `CLAUDE.md` -- written for the
people who develop the agent -- into a Slack channel's prompt; and a document
containing a code fence would have ended the block quoting it. The adversarial
review then caught two more: a document that is not valid UTF-8 raised on every
turn, which would have taken a channel down until somebody changed the commit,
and the conventional names were read before the operator-named ones, so large
defaults could starve the very file this feature exists to load.

## Two audiences, and a card is for blast radius (#262)

The same words were going to the operator who set the deployment up and to a
designer who does not use git. The prompt never said which, so the model could
not have known.

- **The operator** gets the command, the error, the file and line, the id.
- **Everyone else** gets what happened, what it means for their work, and what
  happens next. No command lines, no request ids they cannot act on, no jargon
  they did not use first.
- **Both reading**: write both halves, labelled, shortest first.

The turn now states who asked and whether they are an operator, so this is a
fact the model has rather than an inference. The review caught the case that
would have made it worse than useless: a button approval resumes the thread
with the CLICKING operator's id, so a designer's task approved by an operator
would have come back in operator voice, in the thread the designer is reading.
The parked request now carries who asked for it; the approver remains the
authority for the click.

**And what a card is for.** It exists for what reaches past the channel's own
workspace: the host machine, DNS, money, somebody else's repo, a host nobody
allowed. "I wrote a file in my worktree and now I want to delete it" is none of
those -- it is the work. When something does park, the reply says what the
actual risk is, and never presents a card as though asking permission were
itself the safe habit.

**Names, not assumptions.** This instance is Cosima; the next one may be Daneel
Olivaw LX, or a cat. Any agent is referred to by name, or "it"/"they" when no
name is at hand, and never by a gender inferred from one.

## An @here reaches the agent (#260)

An `@here` asking why nothing was happening reached every human in the channel
and not the one participant able to answer it. A broadcast is addressed to
everyone in the room and the agent is in the room, so `<!here>`, `<!channel>`
and `<!everyone>` are turns now -- the tax #23 removed for DMs, one surface
over.

Slack's own marking is the authority: a real broadcast arrives as a `broadcast`
element in the message's blocks. The review was right that matching the bare
text prefix would have fired on `<!here-not-a-broadcast>` or a pasted snippet,
so the text form is a fallback and is anchored on a complete token. A broadcast
that also mentions the agent is left to `app_mention`, or one message would run
two turns.

## A dead card says so, and stops taking presses (#258)

A request parked at 15:41:37, a deploy restarted the agent at 15:42:38, and the
card went on offering its buttons. Four presses produced four identical "not
pending here" lines, which reads as a broken agent and was the per-boot id rule
(#109) working exactly as designed with nothing saying so.

The message now distinguishes the two ways a request can be absent -- from
before a restart, which is unrecoverable and means ask again, versus already
acted on -- and the card retires itself, keeping the command text and dropping
only the buttons. #94's rule is kept literally: a click that resolves nothing
still must not destroy the only copy of the command.

The review caught that `_resolve` serves the skill-proposal cards too, where
the new call would have raised after the click was acknowledged: silence on
every retry, which is the exact failure this change exists to end.
