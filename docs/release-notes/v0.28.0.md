One change: the waterfall stops dialling rungs it already knows are dead, and
says so when a fallback covers a failure.

## What an upgrade requires

Nothing. No new config key.

## Four places a dead rung was dialled again (#274)

Follow-up to #80, which closed on one half of this. A comment on the upstream
issue filed for it, BerriAI/litellm#37592, prompted a re-read.

### A hung codex rung was never cooled

`codex_llm.py` raised every `httpx.HTTPError`, timeouts included, as
`litellm.APIConnectionError`. LiteLLM's Router refuses to cool that error **by
name**:

    ignored_strings = ["APIConnectionError"]
    if exception_str is not None:     # don't cooldown on litellm api connection errors
        for ignored_string in ignored_strings:
            if ignored_string in exception_str:
                return False

With `num_retries=1`, a hung or unreachable codex was dialled **twice on every
turn**, each attempt paying the full rung timeout -- about 90s per model call
at the 45s default. That is the single largest avoidable latency in the
waterfall, and it was invisible, because a covered failure raises nothing.

A timeout now raises `litellm.Timeout` (408) and any other `httpx.HTTPError`
raises `litellm.InternalServerError` (500). Those are what litellm itself
raises for an HTTP rung in the same state, and the same function cools both:
`408 -> True`, `5xx -> True`, other 4xx -> False.

### A 402 with no marker was re-dialled every turn

OpenRouter's most common 402 -- "This request requires more credits, or fewer
max_tokens ... can only afford N" -- matches none of the budget markers, and
LiteLLM does not cool 402 either. It now parks on its status alone: 402 has no
other reading. A 400 still needs a marker, because it is also "your request was
malformed".

### A covered failure left no trace

Only timeouts and budget errors were logged. When a fallback covers a 429, a
5xx or a 401, nothing raises and litellm logs nothing at WARNING -- so the rung
that failed left no record anywhere. Now:

    waterfall: fb0 failed (InternalServerError 500)

Type and status only; the message can carry the failed request (#72).

### A stated regain date was unbounded

"You will regain access on <date>" is honoured, and now clamped to 31 days. The
date comes out of an error body, so a far-future or typo'd year would otherwise
hold the rung until someone hand-edited the state file. The reason says so:
`for 31 days (the vendor said until 2999-01-01, past the 31-day cap)`.

## Provenance

The branch was built by another session on this machine and handed over. What
was verified before it landed: the `ignored_strings` behaviour read out of the
installed library rather than taken from the report; that 408 and 500 really
are cooled by that same function, so the two replacements are the right ones
and not merely different; and the four behaviours exercised directly. CI ran
the suite against the pinned litellm 1.101.0, which the handing-over session
could not.

## Checks

`selfcheck.py` check 61. The handoff deliberately carried no assertions, on the
global no-tests rule; they were added because **all four failures are silent**
-- a rung dialled twice, a 402 re-dialled forever, a covered failure with no log
line, a park with no ceiling. None of them raises, so nothing else would catch
a regression.
