# shmobster v0.29.0

One change: a channel cannot write the agent it runs under.

## What an upgrade requires

Nothing. No new config key.

It can change behaviour in one case. A channel whose `cwd` or `allow_write`
covers this deployment's own checkout, or the voitta-yolt checkout named by
`exec.yolt_classifier`, can no longer edit files there. The edit fails with
"Operation not permitted" where it used to land. Branch work in
`<repo>.worktrees/` is unaffected, and so is git in the checkout itself.

## The sandbox write-denies the deployment itself (#284)

A channel's tree is the operator's choice, and a wide one -- a parent of
several repos -- can contain the deployment. The grant layer vouches for an
in-tree write on the verb, so two edits ran with no approval card:

- **The classifier.** voitta-yolt is spawned once per command, so a `sed -i` on
  it changed the verdict on the very next command. A channel could turn off its
  own gate.
- **The package and its venv.** A `tee` into either ran unconfined at the next
  restart.

`SELF_FILES` (#147) protected the config and policy files, and #174 the spine;
both cover single files, not the code that reads them.

The seatbelt profile now write-denies, whatever a channel's policy covers:

- this deployment's own checkout, and its venv;
- its state file, its log directory and its trajectories;
- the voitta-yolt checkout that supplies the classifier.

Reads are left alone.

A channel whose tree is the live checkout keeps git working: `git worktree
add` and a commit in a worktree write the main `.git/`, so that gitdir is
carved back -- but only where the channel could already write it, so the carve
never widens a channel. The `.git/hooks` and `.git/config` deny (#184) still
wins inside it.

Verified with `sandbox-exec` against a live-clone layout, all ten probes as
intended:

- refused: writes to the package, the venv and the checkout root; writes to the
  classifier checkout from a parent-of-repos tree; `.git/hooks`; `.git/config`;
- allowed: `.git/` writes, the `.worktrees` sibling, git reads, plain reads;
- a channel whose tree lacks the checkout gets no carve.

## Operator note

This release does not cover backups of the config or policy files. Anything a
channel can read, it can post to Slack without a card, and a backup sitting
next to `shmobster-policies.json` is not one of the two files `SELF_FILES`
protects. Keep backups outside every channel's tree.
