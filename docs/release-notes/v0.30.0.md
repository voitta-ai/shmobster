# shmobster v0.30.0

One change: shmobster can use MCP servers, configured per channel.

## What an upgrade requires

Nothing for an existing channel. This adds a new **optional** policy key, `mcp`;
a channel without it has no MCP tools, which is every channel by default.

## A per-channel MCP client (#299)

shmobster had no MCP client. voitta-rag's search is MCP-only, and a read-only
CRM is the next need; rather than two one-off tools, this is one mechanism that
turns any MCP server into tools the agent can call, each under the same gate as
a shell command.

A channel's `mcp` block names the servers it may use and, per server, which
**tools** -- the allow-list is the menu, so a server that also offers
`delete_memory` does not put it in front of the model unless the policy names it.

    "mcp": {
      "voitta-rag": {
        "url": "http://localhost:58000/mcp/mcp",
        "headers": {"X-User-Name": "${RAG_USER}"},
        "tools": {
          "search": {
            "mode": "read",
            "defaults": {"include_folders": ["email", "contracts"]}
          }
        }
      }
    }

- **`read` runs with no card; `mutate` parks** for a trusted approval and runs
  only once approved -- the same queue and resume as a shell command (#48,
  #169). The classification is the operator's, in the policy.
- **Credentials are injected per server** as request headers, `${VAR}`-resolved
  like `env` (#73). They never enter a prompt, a card or a log, and a parked
  `mutate` stores only the server name, so the headers are re-read from the live
  policy at execution rather than sitting in the queue. Redaction covers them.
- **`defaults`** are arguments the policy forces on every call (voitta-rag must
  get `include_folders` on every search, or it searches every indexed folder);
  they override the model and are dropped from the schema it sees.

The model calls these as `mcp_<server>_<tool>`, and `describe_capabilities`
lists them. The transport is MCP Streamable HTTP over urllib -- no SDK, no
asyncio -- verified against voitta-rag 3.4.4 and a second, unrelated CRM server
unchanged.

Nothing demo-specific is in the code: the servers, tools, folders and
classifications all live in policy.

## Operator note

`mcp` headers may hold credentials, so `shmobster-policies.json` stays
`chmod 600` and gitignored, as it already must for `env`.
