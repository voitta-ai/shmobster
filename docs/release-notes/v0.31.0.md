# shmobster v0.31.0

One change: the liveness watchdog now catches a third wedge shape.

## What an upgrade requires

Nothing. No new config key.

## The watchdog catches a dead message processor (#66 follow-up)

Found live on 2026-10-03: the agent sat deaf in a channel for ~15 hours -- a bot
join and two human @-mentions produced no reply and no log line -- while the
process was up at 0% CPU with two ESTABLISHED sockets, and the #66 watchdog
never tripped.

#66 watches the **socket**: session stability and ping/pong freshness. But in
slack_sdk's builtin client one receive loop reads ping/pong **and** events off
the socket and enqueues them, and a separate `message_processor` thread drains
the queue and runs the listeners. A fresh pong proves the socket is live and
says nothing about the consumer. When the processor dies or wedges, the socket
keeps ponging and the session stays stable -- both #66 signals read healthy --
while events pile up unhandled and the agent goes silent.

The watchdog now adds a third signal: **the message processor is not alive, or
the queue has not drained to empty for the whole timeout.** It is OR'd with the
socket pair, because a dead consumer is a wedge however healthy the socket. An
idle bot does not trip it -- its queue is empty and its processor alive -- which
is why #66 rejected "events delivered" as a signal but "queue not draining" is
safe. The SDK internals it reads (`message_processor`, `message_queue`) are
read defensively: if a future SDK stops exposing them the signal is skipped,
warned once, rather than disarming the original socket guarantee.

As before, the fix is to exit so the supervisor restarts us.
