# shmobster v0.32.0

One change: a spine addition that teaches the agent to run reads without a
needless approval card.

## What an upgrade requires

Nothing. No new config key, no code change -- this is spine content
(`workspace/TOOLS.md`), picked up on the next restart. A deployment that points
`agent.workspace` at its own openclaw-workspace clone, rather than the bundled
`./workspace`, will want to port the same note.

## The agent knows which reads run uncarded (TOOLS.md)

Found live in an unattended channel: a read-only orientation turn parked two
harmless commands, and one then failed after approval. `for f in ...; do python3
-c "import json..."; done` parked on the interpreter; `diff <(git show ...) ...`
parked on the process substitution and then failed exit 2, because the sandbox
runs each command under `/bin/sh -c`, where `<(...)` is a syntax error. Both
were avoidable -- `jq` instead of `python3 -c`, a temp file instead of `<(...)`.

The grant layer decides on the verb, not the intent: it runs a command uncarded
only when it can prove every part is a read. The spine now has a `TOOLS.md`
section (the slot was in the load order but empty) saying which verbs run
uncarded (`cat`, `grep`, `jq`, `git show`, the read-only git subcommands), which
always park (`python3 -c`, `sh -c`, `<(...)`), and that the sandbox shell is not
bash. It is in the system prompt every turn, which is where it has to be: the
command is chosen while composing, not when the agent later calls
`describe_capabilities`. Making that on-demand self-description match is the
separate #292.
