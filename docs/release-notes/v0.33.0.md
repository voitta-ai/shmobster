# shmobster v0.33.0

One change: the agent can edit files in an unattended channel without a card per
edit.

## What an upgrade requires

Nothing. No new config key.

## apply_patch runs uncarded in an unattended channel (#253 follow-up)

Found live: a redesign turn in an unattended channel could not make a single
in-tree file edit without an approval card. The agent edits with `apply_patch` --
its own Update/Add/Delete-File patch tool -- which had no grant rule, so every
edit parked; it then fell back to `python3 -c` and heredocs that park for a worse
reason, hit the step cap, and produced a wall of cards on routine work.

`apply_patch` only writes files -- the same blast radius as `patch` and `tee`
already granted in an unattended channel, confined to the tree by the sandbox.
It now runs there like the rest of that channel's file verbs, heredoc and all.
It stays carded in an ordinary (attended) channel on purpose: a patch can delete
a file, and the uncarded in-tree write set deliberately excludes `rm` for that
reason; an unattended channel already runs `rm`, so there the distinction
stopped mattering.

The spine (`workspace/TOOLS.md`) gains the write half of the same guidance it got
in v0.32.0: edit in-tree with `cat >`/`tee`/`sed`, and know `apply_patch` parks
in an attended channel and runs only unattended.
