# shmobster v0.34.1

A watchdog regression fix and two diagnostics, from a run of repeated wedges on
2026-10-05.

## What an upgrade requires

Nothing. No new config key.

## The watchdog's OR was inverted to AND in v0.31.0 (#66)

The #66 watchdog exits when EITHER socket signal is unhealthy: a session that
never stabilises (churn), or a stable session that stops ponging. v0.31.0's
refactor rewrote that as `unstable AND deaf`, so it fired only when BOTH failed.

The live wedge is a half-open connection: the receive loop blocks in `ssl.recv`,
the session stays stable, and no pong arrives. Under the AND, stable_for stays
~0 while deaf_for grows, so it never fired -- the agent sat deaf and alive, the
watchdog polling and never exiting, until a human restarted it. Restored to OR;
a stable-but-deaf connection now exits within the timeout and the supervisor
restarts into a fresh connection. An idle bot still does not trip it (pongs land
every ~10s on a live session).

## Two diagnostics

- **faulthandler no longer kills the agent.** It was registered `chain=True`, so
  the documented `kill -USR1 <pid>` stack dump also terminated the process
  (SIGUSR1's default action). `chain=False`: dump and continue.
- **The watchdog logs what it sees every 120s** (session, pong age, processor
  and queue staleness), so a wedge it does not catch is readable from the log
  rather than guessed at.
