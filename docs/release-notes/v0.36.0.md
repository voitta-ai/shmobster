# shmobster v0.36.0

Replies render as Markdown in Slack, and a bot's post is no longer answered as
if a human had asked.

## What an upgrade requires

Nothing. No new config key.

## Replies are posted as a Slack markdown block (#320)

The model writes standard Markdown, but a reply posted as bare `text` is read by
Slack as mrkdwn, so `**CRM:**` showed its asterisks. Replies now go out as a
`markdown` block, with `text` kept as the notification fallback and as the copy
read back from history. A reply over the block's 12,000-character cap is posted
as plain text, as before.

Checked against a live post: inside the block, `**bold**`, `[text](url)`,
`<url|text>`, `<@U...>` mentions and `:emoji:` codes all render, so skills that
write Slack-style links need no change.

## A bot sender is not an audience (#320)

A post from a bot (a voice listener posting through a bot token, for example)
carries the bot user's id, which was read as an untrusted human and answered with
the "not an operator, plain language" instruction. A bot sender is now treated
like a webhook post: no audience line.
