# shmobster v0.37.0

A post-answer skill check: the end-of-turn judgment `flag_skill` was supposed to
be and never was.

## What an upgrade requires

Nothing. The new channel policy key `skill_check` is off by default; a channel
without it behaves exactly as before.

## Post-answer skill check (#232, #303)

`flag_skill` is a tool the model calls while composing, so the judgment about a
turn's conclusion is asked for before the conclusion exists. Two rewrites of the
bar text (#211) did not move it: the most skill-worthy turns kept going
unflagged.

With `"skill_check": true` in a channel's policy (and learning configured), a
turn whose answer rests on content a `run_shell` or `web_fetch` returned gets
one bounded model call after the answer: `FLAG: <name> | <why>` parks a proposal
through the same path as `flag_skill`, so the same card surfaces; `NO: <reason>`
is recorded in the trajectory as `flag_considered`, so the check's "no" can be
told apart from its not having run. It never re-judges a turn that flagged
in-composition, and an unparseable verdict parks nothing.

Cost: one extra model call, before the reply, on candidate turns in opted-in
channels only. Not a step-count floor -- the missed turns were among the
cheapest in their threads.
