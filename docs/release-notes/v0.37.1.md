# shmobster v0.37.1

shmobster now names the voitta-yolt release it is tested against, and says so at
boot.

## What an upgrade requires

Put the voitta-yolt clone on the pinned tag before restarting:

    git -C /path/to/voitta-yolt fetch --tags
    git -C /path/to/voitta-yolt checkout --detach v2.8.0

The boot floor is unchanged (it still refuses a classifier older than 2.0.1).

## The yolt clone is pinned (`yolt_gate.YOLT_PIN = "v2.8.0"`)

The classifier is a sibling clone, not a package: nothing installs a version, and
a `git pull` in that clone changes every verdict live, between restarts. On
2026-10-07 another session pulled it from v2.4.0 to v2.7.0 without knowing the
agent read it.

At boot the agent now logs `yolt: v2.8.0 (pinned)` when the clone sits exactly on
the pinned tag, and a warning naming what it found and the checkout that fixes it
when it does not. A warning rather than a refusal: a refused boot is a launchd
crash loop, and a moved clone is a review problem, not an outage. The README's
upgrade steps now check out the tag instead of pulling.

v2.8.0 over 2.4.0 does not widen what the agent runs without a card: shmobster
promotes only its own allow-listed reads from YOLT's `unknown`, and 2.5-2.8 add
no `safe` verdicts.
