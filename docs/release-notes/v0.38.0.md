# shmobster v0.38.0

`vercel` becomes a per-channel grant, scoped to Vercel projects.

## What an upgrade requires

Nothing for channels that do not use vercel: without a `vercel` key in a channel
policy, every `vercel` command parks, as before. To grant one, add the key and
the channel's token (README, channel policy keys):

    "env": {"VERCEL_TOKEN": "${SOME_TEAM_TOKEN}"},
    "vercel": {
      "team": "acme-enterprises",
      "org_id": "team_...",
      "projects": {"scrooge-banking": "prj_..."},
      "writes": false
    }

## The vercel grant (#327, #328)

The policy names the projects a channel may reach, as `aws_profile` names the AWS
account. A command is granted only when every target it names resolves to an
allowed project: `--scope`/`--team` (read, never skipped), the channel's
`VERCEL_ORG_ID`/`VERCEL_PROJECT_ID`, the tree's `.vercel/project.json` (evidence,
never the policy), or a generated deployment URL matched exactly.

- Reads (`ls`, `inspect`, `logs`, `env ls`, team `project ls`/`domains ls`/
  `alias ls`) run with no card; with `"writes": true`, also `deploy`, `promote`,
  `rollback` and `env add`/`rm`.
- Every granted command must carry `--token "$VERCEL_TOKEN"` from the channel's
  `env`. Without it the CLI would use the operator's global login; a literal
  token parks, since it would sit in the recorded command.
- Always parks: `env pull`, `link`, `alias set`/`rm`, custom domains and `dpl_`
  IDs, a dynamic `--scope`, `--cwd` and the config-path flags, unknown flags, a
  monorepo `repo.json`, any `VERCEL_*` in `env_passthrough`, a `deploy <dir>`
  outside the channel tree, and any vercel command sharing a command line with a
  write (`cp`, `mv`, a `>` redirect) that could rewrite the link first.

Known residual: another turn in the same channel can rewrite the link between
this turn's check and its run. Closing that needs revalidation at exec time.
