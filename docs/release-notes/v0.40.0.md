# shmobster v0.40.0

The agent can answer on Signal as well as Slack, through voitta-gateway. The grant layer now vouches for every command it runs. The classifier pin moves to voitta-yolt v2.17.0.

## What an upgrade requires

- **voitta-yolt v2.17.0.** Move the classifier clone before restarting:
  - Run `git -C <voitta-yolt> fetch --tags && git -C <voitta-yolt> checkout --detach v2.17.0`.
  - Then probe it with `python3 <voitta-yolt>/hooks/grammar_classifier.py --no-user-allow --cwd / 'rm -rf /tmp/probe'`. Expect `"decision": "unsafe"`.
  - A clone at any other tag boots with a warning.
- **Dependencies changed** (aiohttp, certifi, filelock, litellm). Run `.venv/bin/pip install --require-hashes -r requirements.txt`.
- **Signal is optional.** Without a `gateway` section, nothing changes. To turn it on:
  - Give the agent a consumer in the gateway's `gateway.yaml`.
  - Add the section below. `token` is a `${VAR}` reference like every credential (#73), so set the variable in the service's environment before you add the section. An unset variable stops the boot.
  - Add Signal users to `trusted_users` as `signal:<ACI>`.

```json
"gateway": {
  "url": "http://127.0.0.1:8700",
  "token": "${SHMOBSTER_GATEWAY_TOKEN}",
  "consumer": "shmobster",
  "conversations": {"team": {"link": "C0123456789", "mirror": false}}
}
```

## Signal through voitta-gateway (#336, #381, #382, #386)

- **Turns.** A message the gateway addresses to the agent is a turn, answered in the same conversation.
  - The answer quotes the question, so a follow-up that quotes the answer comes back to this agent.
  - Markdown becomes Signal's bold, italic, strikethrough and monospace.
  - Long answers are split to Signal's 2000-byte limit.
- **Approvals are text.**
  - A card names the request id. If a trusted user's whole message is `approve <id>` or `deny <id>`, it resolves the request without the model, the way a button does on Slack, and the task resumes.
  - Cards show the whole command, and a classifier refusal reads as a refusal.
  - `deny_command` is the typed twin of the Deny button on every surface.
- **Policy.** A conversation with a `link` shares that Slack channel's policy. A DM uses `default_policy`.
- **Mirroring** is off by default. With `mirror: true`, each turn's question and final answer are copied between the linked Slack channel and Signal.
  - Mirrored text is escaped, scrubbed, and marked so neither side's history reads it as the agent's own words.
  - Cards stay where they were posted.
- **People on Signal** appear as a stable handle (`Signal user 3f9a2c`), never by the profile name they chose.

## Commands (#357, #359, #369, #370, #375)

- **Every command is vouched for by the grant layer's own rules (#375).** A segment none of them covers parks. An attended `curl -o FILE` now cards; unattended channels still grant it.
- **More reads run without a card (#369):**
  - `date`;
  - `git rev-list`;
  - `whoami`;
  - `node -v` and `node --check`;
  - `git config` lookups;
  - `echo`, `pwd`, `true` and `sleep`.
- **Redirect targets, heredocs and `rg` (#370)** are judged the way the shell runs them.
- **Long commands (#357).** A long command is cut on its Slack card, with a link to the full text.
- **Cards that cannot be posted (#359).** The request is withdrawn instead of holding the thread.

## The classifier: voitta-yolt v2.9.0 -> v2.17.0

Each step was replayed against yolt's public probe corpus (334 commands) and a private set before the pin moved, with nothing weaker at any step. After the upgrade, these ask instead of passing:
- a command substitution in a redirect target or heredoc;
- a command yolt cannot parse;
- a relative write after a `cd`;
- a shell running a script it cannot see (`curl … | sh`, `bash file.sh`).

A literal heredoc fed to a shell is judged by its lines.
