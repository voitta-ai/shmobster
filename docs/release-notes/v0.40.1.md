# shmobster v0.40.1

On a shared Signal account, the agent now says who it is, and the gateway decides which groups it is in.

## What an upgrade requires

- **voitta-gateway with `GET /v1/conversations`** (voitta-gateway#16). The agent asks the gateway which groups it serves. An older gateway answers 404: turns still work, but announcements reach no Signal group. voitta-gateway#17 adds the gateway's `/help`.
- **Move `gateway.conversations` into policy.** With a gateway `url` set, the old key stops the boot with a message saying where its entries go:
  - each `"<label>": {link, mirror}` becomes `"signal:<label>": {link, mirror}` under `channel_policies`, in the policies file when there is one (`SHMOBSTER_POLICIES`, default `shmobster-policies.json`), else in the main config;
  - an entry with a `link` keeps sharing that Slack channel's policy, `unattended` included;
  - an entry that only set `"mirror": false` can simply be dropped.
- **`gateway.consumer` must be the token's consumer name in `gateway.yaml`** (default `shmobster`). The agent now keeps only groups naming that consumer, recognises its own past messages by it, and answers `/help <name>` for it. A mismatch shows as a boot warning for each `signal:` policy.
- **Optional:** `gateway.account_name`, the shared account's Signal profile name, so the agent knows that name means the account.
- No new dependencies. The yolt pin is unchanged at v2.17.0.

## The gateway owns presence (#393)

- **Which groups** the agent is in is decided only in the gateway's `gateway.yaml`. The agent asks at boot and for each announcement, and keeps only groups that name its consumer or are open to all, so an admin token never announces into another agent's group.
- **What the agent may do** in a group is its policy entry, `signal:<label>`:
  - its own envelope;
  - or `link` to share a Slack channel's policy (other keys in a linked entry are ignored, with a boot warning);
  - `mirror` lives here too.
- **No entry, or an entry with only `mirror`, means `default_policy`.** A routing-only entry never becomes an empty, unbounded envelope.
- **Boot warnings:**
  - a policy for a group the gateway does not route to this consumer;
  - a gateway too old to list groups (logged with its HTTP status).
- **No gateway, no change:** a deployment without a gateway `url` never asks for groups (#396).

## Who is on the account (#392, #394, #396)

- **`/help`.** The gateway answers a bare `/help` with the agents on the account and how to reach each. `/help <label>` (also after an @mention of the account) reaches the agent, which answers without the model:
  - what it is and how to reach it;
  - its GitHub repositories in that conversation;
  - whether it asks before changing anything.

  No paths are shown, since anyone the gateway lets in can ask.
- **Release announcements on Signal** end with a line saying who the agent is, how to reach it, and `/help`.
- **No double signature.** The gateway signs every message with the agent's label. The agent's own history lines are now shown unsigned, and a leading `<label>:` is dropped before sending, so replies no longer read "Ada: Ada: ...".
- **The agent knows the shared account.** It sees an @mention of the account as one of itself, and knows the account's profile name (`gateway.account_name`) is shared.
