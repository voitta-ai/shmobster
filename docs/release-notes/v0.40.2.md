# shmobster v0.40.2

Failures read as one short line, dead model rungs are parked and announced, and a resumed task keeps the files it started with.

## What an upgrade requires

Nothing. No config, dependency or pin changes; the yolt pin stays at v2.17.0.

## A failed turn says so in one line (#354)

- A turn that fails posts one short line instead of the exception: "No language model is available right now ... try again in a few minutes" for errors that pass on their own (rate limit, timeout, 5xx, connection), otherwise "Something went wrong and I could not finish this".
- The same line on Slack and Signal. Before, Signal posted the whole router dump, and a mirrored conversation copied it into Slack.
- The exception goes to the log only, with the channel and thread (Slack) or message (Signal), so it can be matched to the turn.

## Dead model rungs are parked and announced (#358)

- A rung whose model is gone (a retired model, a dropped free tier) or refused for the plan is parked instead of being dialled every turn: 1 hour first, doubling on repeat up to 24 hours. Fixing the rung's model in the config un-parks it at once.
- It is logged at ERROR with the rung, a fixed reason and the vendor's suggested replacement model when it names one; the vendor's error text is never copied.
- An operator notice is posted once, in the thread of the next Slack turn a trusted user starts, after its reply and approval cards. Client channels, other people's DMs and Signal conversations never get it; until then it waits in the state file.
- A request-shaped failure (an attachment a model cannot read, a parameter refused for one request) parks nothing.

## A resumed task keeps its files (#367)

- When a task parks for approval and resumes after the click, the files attached to the mention that started it are read again for the resumed turn, so the model no longer asks for them a second time.
- They are kept while the task is under way (parked, running, or resuming), including through a "how is it going?" message; files from later mentions in the same busy thread are added, up to the latest 10.
- They are fetched only when the click can resume, and a failed download becomes a note instead of stopping the task.
- A typed `approve <id>` continues in the approver's own turn and does not carry them yet.

## Also

- **Release announcements are Markdown (#399).** They read cleanly on Signal (bold version, `release notes (<url>)`), and on Slack as before.
- **A git call with no subcommand** parks as `git: no subcommand` instead of `git None: not a local write` (#398).
