# shmobster v0.40.3

shmobster serves only closed Signal groups, names the people in them, and can mention them back.

## What an upgrade requires

- **voitta-gateway with `GET /v1/conversations/{label}/members`** (voitta-gateway#18) deployed first. Without it, no group's members can be checked, so every Signal group is refused (DMs are unaffected).
- **`admit: members`** on each Signal group in the gateway's `gateway.yaml`, so every member's message gets through, not only allowlisted senders'.
- **Close each group** the agent should serve, in the Signal app: Group link off; Permissions, Add members, Only admins (README, Signal). A group left open is refused.
- No shmobster config, dependency or pin changes.

## Closed groups only (#401, #402)

- shmobster serves a Signal group only while the gateway reports it closed: no group link, and only admins can add members. This is a fixed rule, not a setting (CLAUDE.md, "Signal groups").
- An open group, or one whose members cannot be checked, is refused, with one line in the group at most once an hour saying why and how to close it.
- Nothing reaches a group that is not closed, whatever the path: replies, command output after an approval, cards (a withheld card is withdrawn), alerts, release announcements and mirrored Slack answers. A group that opens while a turn runs hears nothing more from it.
- The boot log names each served group that is open or could not be checked.

## People and other agents (#401)

- People in a group are named by the operator's `persons` name in `gateway.yaml`, else a stable handle (`Signal user 3f9a2c`); never the profile name they chose. Before, a mention of anyone but the agent read "@someone".
- The agent can mention them back: `@<that name>` in a reply goes out as a real Signal mention (not inside code, URLs or addresses).
- A `persons` entry with `agent: true` is another agent: the agent answers at most 3 of its messages in a row in a group until a person speaks to it there. DMs are not counted.
