# shmobster v0.42.0

Uncarded git now runs only in the channel's own repository. The sandbox stops a command from swapping the repository git loads. And two failures that ended a turn with "Something went wrong" are gone.

## What an upgrade requires

- **Dependencies changed**: litellm 1.109.1 and tree-sitter 0.26.1 (#417). Run `pip install --require-hashes -r requirements.txt` in the deployment's venv before restarting. The yolt pin is unchanged.
- **`workspace/SOUL.md` gained three bullets** (#415, #347). A deployment whose `agent.workspace` points at its own copy of the workspace gets them only when they are copied over.
- **Git has new limits in channels.** Each of these used to run and now gets a card or fails; details under "Git, pinned" below.
  - Uncarded git runs only in the channel's checkout (its `cwd`, which must hold a `.git` directory) or in a worktree under `<cwd>.worktrees`. A channel whose `cwd` is a parent directory, or is itself a linked worktree, loses uncarded git.
  - In attended channels, git after a write in the same command gets a card; `git add` and `git commit` are exempt.
  - `git init`, `git clone`, `git worktree add/remove/prune` and `git submodule add` now fail inside a channel, approved or not. An operator runs them.

## Fixed: turns that ended in "Something went wrong" (#418)

- `flag` (the agent proposing a skill) crashed on every call whose name contained a long word, and took the turn with it. The same crash stopped the resumed turn after an approval.
- When two turns ran at once in one channel, the one that finished first posted the other thread's approval cards, and its skill-proposal cards, in its own thread. Each thread now posts only its own cards; the other thread's turn posts the rest when it ends, including after a crash.

## Git, pinned (#344, #422, #423)

A git read is only as safe as the repository configuration it loads, and that configuration can name commands for git to run.

- **Where git is granted.** Git runs without a card only in the channel's checkout or a worktree root under `<cwd>.worktrees`. A worktree's `.git` pointer must name a gitdir directly under the checkout's `.git/worktrees/`, and that gitdir's `commondir` must lead back to the checkout. A symlinked `.git`, a pointer that leads anywhere else, and a checkout whose `.git` is a file are all refused.
- **How the directory is tracked.** The grant layer tracks every directory bash could be in. After `;`, `||`, a newline or `&` that can be several; a `cd` inside a pipeline moves nothing; and anything it cannot model counts as unknown and parks.
- **Options and environment that park.** git global options are an allowlist (`--no-pager`, `-P`, `--no-optional-locks`, `--literal-pathspecs`, `--no-replace-objects`, `--no-advice`, `-C <dir>`). `-c` / `--config-env` park, and so does a channel `env` that sets any `GIT_*` name. An unattended push whose directory is unknown parks.
- **Sandboxed probes.** The grant layer's own git queries (`commit_allowed`, and `remote_url` for an unattended push) run inside the sandbox, with the network denied and no credential helper. Anything a repository's config makes them run gets no network and no credentials.
- **What the sandbox freezes.** The sandbox no longer lets a command create, overwrite, delete or rename the entries that decide which repository git loads: every `.git`, `hooks` under one, `.git/worktrees` and `.git/modules` and the entries in them, and a worktree's `commondir` / `gitdir`. The #184 denies on `config` and `hooks/` matched paths, and renaming a prebuilt directory into place got past them. Index, objects and refs stay writable, so add, commit, stash and branch work as before.
- `git cherry` is a read.

## More runs without a card

- `git grep`, except `-O` / `--open-files-in-pager`, `--textconv` and `--ext-grep` (#414).
- A double-quoted word with backslash escapes but no `$`, `$(…)` or backquote is read the way bash reads it, instead of being refused as "takes shell rules to read" (#419). For example, `curl -s -w "\nHTTP:%{http_code}\n" <url>` to an allowed host.
- In an unattended channel, a read verb redirected into a file (`jq … > f`, `grep … > f`) runs, as `tee` already did (#368).

## Also

- **Gateway (Signal) attachments** reach the model and are saved the way Slack's are, including on the turn that resumes after an approval (#416, closes #413).
- **SOUL:**
  - "It would park" is not "I can't": run the command and let it park, trying the cheapest check first (#415).
  - Never name your own tools to people (#415).
  - Prefer the read verbs that run without a card over interpreter one-liners (#347).
- **Vercel:** a channel with a `vercel` policy is told the calling convention (`--scope`, `--token "$VERCEL_TOKEN"`) and its projects. `docs/VERCEL.md` covers channel setup (#337).
- **CI:** a coverage report on each PR, with checks and coverage badges in the README (#420).
