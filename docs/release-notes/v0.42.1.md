# shmobster v0.42.1

Fewer cards for reads, and a GitHub repo whitelist that holds for every part of a command, not just the first one it notices.

## What an upgrade requires

- No config, dependency or pin changes.

## Repo whitelist (`github_repos`), checked per command segment (#425)

- **A false positive is gone.** A local path beside a `gh` command (`jq . app/data.json; gh run list`) was refused as repo `app/data.json`, and `grep -R pat dir; gh …` would have read `pat` as a repo. Only the segments that run `gh` are scanned now.
- **Holes closed, mostly older than this release:**
  - Every `gh` segment's repo is checked; before, only the first was.
  - A `gh` or `git` segment that names no repo has its checkout's origin checked, even when another segment names an allowed repo.
  - A `GH_REPO=` written in another segment is an extra target to check, never a substitute for a segment's own target.
  - A `gh api` segment naming no repo refuses, whatever other segments name.
  - Separators written without spaces (`ok;gh`, `&&gh`, `$(gh …)`, backquotes, `(gh …)`) no longer hide `gh` or `git`, or a `-C` / `cd` glued to them.

## More runs without a card (#425)

- `cut` and `comm`.
- `uniq` with at most one input. A second operand (the file it writes) or a glob or brace list still parks.
- `cd d && cat > f <<EOF`: the redirect is judged against the last command, as bash binds it, so this is granted like the same heredoc without the `cd`.

## Also

- **Skill drafts** succeed when the model puts a sentence or a code fence around the SKILL.md (#425). A draft that is still rejected logs how it began.
