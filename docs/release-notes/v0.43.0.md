# shmobster v0.43.0

Signal answers what a sender meant after an edit, approval cards can't be dressed up by the command they show, a short rate limit no longer ends a turn, and the state file survives concurrent writers.

## What an upgrade requires

- No config, dependency or pin changes.
- Two things to know, neither a step:
  - The state file now gets a sibling lock file, `shmobster-state.json.lock` (or `<SHMOBSTER_STATE>.lock`), created 0600. It is gitignored.
  - Signal edit handling needs a gateway that emits `message.edited`; current gateways do. An older one simply never sends edits, and nothing else changes.

## Signal: edits are answered (#404)

- **An edit before the agent starts answering replaces the text it answers**, so a stub sent first and filled in by an edit gets one answer, to the full text.
- **An edit during or after the answer gets one follow-up turn** that quotes the original and says it was edited. A message's turns run one at a time, in order; edits that pile up while one waits collapse into the latest.
- **Ignored:** edits to messages the agent never took as a turn (not addressed to it, refused by the closed-group gate or the loop guard, or an `approve` / `deny` / `/help`), and edits more than two days after the answer.
- Follow-ups pass the same closed-group gate and loop guard as any message.

## Approval cards (#376)

- **The command on a card is inert.** `&`, `<` and `>` are escaped, and runs of backticks can't close the code block, so a command can't put its own text, mentions or links beside the Approve button. The command that runs is unchanged.
- **A card that had to alter the display says so**, and points to the full-command reply, which is posted as exact plain text in that case so it copies byte for byte.
- **A cut full-command reply says TRUNCATED**, with how much of the command fits.
- **Failed cards retry on their own.** A card Slack refuses for a transient reason backs off (30s doubling to 10 minutes, or the 429's Retry-After) and reposts on a timer, in its own thread only. It is withdrawn only after failures spanning 15 minutes, never on a rate limit. A card is never posted without the full-command reply it refers to.

## Model fallback (#351)

- **A short 429 on the primary is waited out**: a stated retry delay of up to 60s, then one retry of the same model before falling back.
- A fallback that answers 404 for a reason not already known to mean "dead" logs a warning naming the rung, so a stale slug is easy to spot.
- A failed skill draft posts a plain line, not the provider's error.

## State file (#363)

- Writes are atomic (temp file, fsync, rename) and keep the file's mode.
- Read-modify-write of a key is locked within the process and across processes, so a restart overlap no longer loses a parked vendor, a dead-rung record or a thread mark. If the lock can't be taken, the write is refused and logged rather than done unguarded.

## For contributors

- **The sensitive-terms gate** (`scripts/check-sensitive-terms.sh`) catches wordlist names inside identifiers (`AcmeCorpThing`, `ACMEClient`, `ACME_PROD`) and fails closed when the scan can't run (no python3, an unreadable wordlist or path, an invalid pattern) (#339).
- **The pre-push hook** scans only commit messages the destination doesn't already have, asked of the destination itself, so merging master into a branch no longer trips on master's history (#339).
- Example instance names in docs and selfcheck are now neutral (#427).
