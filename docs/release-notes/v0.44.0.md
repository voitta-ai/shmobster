# shmobster v0.44.0

`web_fetch` gets its own host list, so a channel can read any public page someone pastes without opening shell `curl` to every host, and a fetch now connects to the address it checked and ends on time.

## What an upgrade requires

- No dependency or pin changes, and no config change unless you want the new key.
- **Nothing changes for a channel that doesn't set `read_domains`.** `web_fetch` falls back to `allow_domains`, as before.

## `read_domains` (#434)

- **New policy key, read only by `web_fetch`.** `"read_domains": ["*"]` lets the agent read any public page with no approval card. Shell `curl`, `wget` and `git` still answer only to `allow_domains`, so a pasted link no longer needs the network opened for every command.
- **Why not `allow_domains: ["*"]`:** that also opens curl, which can carry credentials (netrc, cookies, config files, proxy env) and request bodies, follows redirects, and reaches anything a name resolves to. `web_fetch` sends no credentials, refuses inward addresses, never follows a redirect, and fences the page as data.
- `describe_capabilities` lists the hosts `web_fetch` can read on their own line ("any public host" for `*`), and the tool description steers the model to it, not curl, for a pasted link.

## `web_fetch` hardening (#434)

- **Connects to the address it checked.** The name is looked up once, every address must be public, and the connection goes to those addresses. The certificate is still verified against the hostname. This closes the DNS-rebinding gap that a `*` list would have made exploitable. Proxy settings from the environment are ignored.
- **Falls back across addresses within one deadline**, trying up to four with IPv6 and IPv4 alternating (RFC 8305), so a host with no IPv6 route still reaches its IPv4 records.
- **One absolute 30s deadline across TLS, headers and body.** A server dripping a byte at a time used to hold a turn indefinitely; the fetch's socket is now shut at the deadline. A body cut short is used as far as it arrived.
- **Remaining risk, documented in the README:** injected text on a fetched page can still lead the agent to fetch a URL with data in its query string.
