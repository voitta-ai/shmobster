A bug fix. A non-trusted click on an approval card no longer destroys the
parked command, and the refusal no longer blames the agent for it.

## The refused click (#94)

A user asked a read-only question. The turn parked a mutating command, the
approval card went up, and a non-trusted user clicked **Approve**. Three
defects fired at once, and together they turned a gate that worked into an hour
of archaeology.

**The refusal destroyed the card.** The button handler called `chat_update`
unconditionally, before anything had decided the click counted, so the card
body and its buttons were replaced by the refusal text. Meanwhile the trust
gate refuses *before* reaching `approvals.pop`, so the request was still in the
queue -- and `claim_unsurfaced` had already marked it `surfaced`, so it would
never be rendered again.

The request was orphaned: still parked, invisible, unapprovable, and the only
copy of the command text overwritten. A stranger's click permanently killed a
command a trusted user was about to approve.

**The refusal blamed the wrong actor.** The alert hedges with "This can be my
own doing, not necessarily their request". That wording is right for a
model-initiated `set_policy` -- it is what #59 fixed -- but a button press has
exactly one possible actor, because the model cannot click. The agent read its
own alert, concluded it had self-initiated a privileged action during a
read-only summary, and reported that to the trusted user. It had not, and the
next hour went into looking for a mutation that never happened.

**Nothing recorded what was parked.** `run_shell`, the YOLT gate and the
classifier all log nothing, so once the card was overwritten the command
existed only in the process's in-memory queue. Asked what the request had been,
the agent had no tool that could answer -- and correctly said so, then pointed
at run logs that did not exist.

### What changed

A click that resolves nothing no longer touches the card. The buttons stay
live for a trusted user and the command stays readable.

The refusal now names the human who clicked, which button they pressed, and the
command that did not run:

    :warning: @someone clicked *Approve* on request [3], but only trusted users
    may act on a parked command -- nothing ran and it is still parked.
    @trusted for visibility.
    ```gh issue create ...```

The click is exactly when someone asks "what was parked?", so the alarm answers
it. On a stale card -- a request already claimed, denied, evicted, or cleared by
a restart -- it says the request is no longer pending rather than asserting a
queue entry that is not there. The #59 wording is untouched on the model path,
where the hedge is true.

Each user gets one alert per request. Leaving the card standing also leaves its
buttons re-clickable, and the destructive rewrite had been swallowing the second
click by accident; now it is deliberate. The alert is only counted as spent once
Slack accepts it, so a transient failure does not leave the trusted users
unnotified and every retry suppressed as already-notified.

Parking and claiming are logged, so a parked command survives the loss of its
card. The command is scrubbed at the emission site rather than by the formatter
the Slack ingest installs at boot: `approvals` is ingest-agnostic and reachable
from a script or the next ingest, and a log file outlives the card that was the
whole reason for logging. Both log lines are emitted *before* the queue is
mutated -- redaction is fail-closed (#72), and a raise on either side of the
mutation would leave exactly the kind of orphan this release is about.

## Also

`slack_post`'s description invited the model to deliver its answer through the
tool. That posts to the channel while the real reply goes to the thread, so a
question and its answer end up in different places -- which is what happened in
the thread above, and made the answer look lost. The tool now says the final
reply is already posted in-thread, and to pass `thread_ts` when posting into a
thread deliberately.

## Upgrading

    git pull
    .venv/bin/pip install -r requirements.txt
    .venv/bin/python selfcheck.py
    deploy/service.sh restart

- **Nothing to change.** No new config key, no new dependency.
- **The restart clears the approval queue**, as every restart does. A command
  parked before the restart has to be asked for again.
- **Worth knowing:** approval activity now appears in `logs/shmobster.err.log`
  as `approvals: parked [id] ...` and `approvals: claimed [id] ...`.
