Three reliability fixes from the backlog triage. One new config key, optional.

## A hung rung can no longer hold a turn (#125)

Every waterfall rung now carries a per-request timeout: `waterfall_timeout_sec`
(default 45) unless the vendor row overrides it with its own `timeout_sec`. A
rung that accepts the connection and never answers becomes a `Timeout` the
Router fails over -- logged as a `waterfall:` line, so a rung that keeps timing
out reads as a pattern -- instead of holding the turn for litellm's 600s
default while the fallbacks never run.

## `service.sh update` survives its own race (#92)

`launchctl bootout` returns before teardown finishes, so update's immediate
bootstrap could fail with "Input/output error" and leave the agent DOWN.
update now waits for the old instance to leave the domain, retries the
bootstrap three times with each attempt's real launchctl error echoed, and on
total failure prints the exact recovery command.

## Dead channels announce themselves at boot (#93)

Every configured channel is probed once at startup; a stale id or a channel
the bot was never invited to logs a warning naming the channel and what the
error means (`channel_not_found` = not a member or dead id, never a bad
token), instead of surfacing as a failed post mid-turn.

## Upgrading

    git pull
    .venv/bin/pip install -r requirements.txt
    .venv/bin/python selfcheck.py
    deploy/service.sh restart

Nothing to change. Add `waterfall_timeout_sec` (or a per-row `timeout_sec` for
a deliberately slow rung) only if the 45s default does not suit.
