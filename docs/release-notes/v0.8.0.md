The security model arrived this cycle: five gates, each one documented and
covered by `selfcheck.py`, and self-modification closed at the config and at
the prompt. That makes this the release with the longest operator to-do list
of any so far -- four new config keys, one of them required in every channel,
a voitta-yolt version range enforced at startup, and a set of commands that
used to run silently and now ask first.

Read the next section before upgrading. An upgrade that skips it does not
fail loudly; it changes what a channel can do without saying so.

## What an upgrade requires

**1. Add `allow_domains` to each channel's policy (#149).**

A fetch runs uncarded only when every host it names is in the channel's
`allow_domains`. A channel with no list cards *every* `curl`, `wget`,
`git fetch`, `git pull` and `git ls-remote`. That is the right default for a
channel nobody has thought about, and a surprise for one whose normal work
pulls from GitHub:

    "allow_domains": ["github.com", "api.github.com", "*.githubusercontent.com"]

**2. Run voitta-yolt >= 1.6.0, < 2.0.0 (#148, #177).**

shmobster passes `--no-user-allow`, which landed in voitta-yolt 1.2.0
(voitta-ai/voitta-yolt#126), but the supported floor is **1.6.0**: four
write-target fixes closed in between, one of which (voitta-ai/voitta-yolt#128,
1.3.0) is the one that mattered here -- before it,
`echo x > $HOME/.ssh/authorized_keys` classified *safe*, which on this side
means auto-run with no card.

**2.0.0 is not supported.** It collapses "we deliberately delegate this" and
"we could not classify this" into one `unknown` verdict, and a consumer that
must fail closed on the second has no choice but to fail closed on the first --
so every ordinary read in a channel parks for an approval card. Tracked as
#177 against voitta-ai/voitta-yolt#144. An operator who runs
`claude plugin update` and gets the newest version should know why it is the
wrong one here.

Startup enforces the range rather than trusting the pin: the preflight probe
is `cat /dev/null`, a command 2.0.0 delegates, so a classifier that cards
every read is caught at boot instead of in a channel.

**3. Set `logging.path`, then `chmod 600` the existing log (#155).**

With the key set, the agent owns a rotated 0600 file. Without it nothing
changes and the launchd-redirected log keeps growing -- **185 MB, mode 0644**
on the live box when this was written. launchd's `Umask` (now in the plist
sample) applies only to files it creates, so the existing log keeps its mode
until someone chmods or deletes it.

Trajectories are now pruned to `learning.trajectory_days` (default 14) at
startup. Nothing to do, but the first restart after this upgrade deletes
files.

## Commands that used to run silently now ask first

`gh pr create`, `gh pr merge`, `git push`, `codex exec`, and any fetch to a
host outside the channel's `allow_domains`. That is the change, not a fault.

Two causes. "Safe" now means YOLT's rules and nothing else (#148): `classify()`
passes `--no-user-allow`, and `yolt_gate.preflight()` asserts at boot that
`allow_patterns` came back `0`. **123 inherited patterns before, 0 after** --
the operator's own terminal allow-list no longer decides what a channel runs
uncarded. And egress needs a card unless the channel was given the host (#149),
enforced in `run_shell` *and* in the grant layer's read-only fallback, which
otherwise handed back the grant the demotion had just refused.

## A command's environment is built from an allowlist (#112)

A floor (`PATH`, `HOME`, `USER`, `LANG`/`LC_*`, `TERM`, `TMPDIR`, `SHELL`)
plus git's per-process config, the channel's `AWS_PROFILE`, its policy `env`,
and a new `env_passthrough` list of host variable *names*. `SCOPED_ENV_NAMES`
is gone: with a floor there is nothing to subtract. Measured on the live host:
**152 variables -> 20, 29 credential-shaped -> 0**.

## The deployment cannot edit itself (#147, #174)

`config.SELF_FILES` -- the deployment's own `shmobster-config.json` and
`shmobster-policies.json` -- is refused by `policy.check` with a reason and
denied `file-read*`/`file-write*` in the sandbox profile. The write deny
covers rename, unlink and link, so `mv`, `cp`, `sed -i`, `rm`, `ln -sf`,
hardlink-then-rename and the `$var` and `sh -c` forms all fail with the file
byte-identical.

#174 closed the one file that stopped short of: `spine.load_system_prompt()`
reads `SOUL.md`, `USER.md` and `CALIBRATION.md`, and the agent could rewrite
its own standing prompt. It cannot now.

## A parked approval no longer ends the task (#169)

A button click used to run the command, rewrite the card with its output, and
stop -- `_resolve` -> `run_approved` -> `tools.execute` -> `chat_update` was
the whole path, and nothing went back to the model. Correct for a one-shot
mutation, wrong for a task whose middle step parked: the output reached the
channel and the task silently stopped, one human re-mention per step. The turn
now resumes through `handler.resume`, which also owns the "is anything else
still parked in this thread" rule.

## A refused command skips the grant layer, and its card says so (#172)

voitta-yolt 2.0.0 adds a fourth verdict, `deny`: an already-unsafe command a
git-state predicate refuses outright, rather than one it wants a human asked
about. Nothing here broke on it -- every consumer compares against `"safe"`,
so a new verdict parks -- but the handling is now chosen rather than
incidental: a refusal skips the grant layer, and its card says it was refused
instead of queued. The general shape is worth keeping: **a new verdict nobody
handles sends the most restrictive answer down the least restrictive path**,
which is why the comparison is against `"safe"` and not against `"unsafe"`.

## The agent reports its real envelope (#9)

A `describe_capabilities` tool reads the channel's envelope out of its policy
-- `cwd`, `github_repos`, `aws_profile`, `allow_domains`, the **names** of its
policy `env` and `env_passthrough`, its `allow_read`/`allow_write`/`exclude`,
its skill menu, and what the grant layer runs without a card. Names, never
values. A tool rather than a per-turn prompt block, so the standing prompt
pays nothing for it, and "what can you do" is answered from the policy instead
of from prose that drifts.

## Smaller, from the security re-audit

- **The attachment bearer goes to slack.com over https, and nowhere else
  (#153).** `_fetch` attached the workspace-wide bot token to whatever
  `url_private_download` the event carried, and `urlopen` follows redirects by
  default while copying request headers to the next hop -- confirmed on Python
  3.14: a 302 to another host receives the bearer. Slack controls those URLs,
  so likelihood was low and the credential is workspace-wide, so the fix is a
  host check.
- **Do not phone home (#156).** `litellm.telemetry` was left at its library
  default. Nothing was found calling out, so this is defence in depth -- but a
  dependency bump can flip a default back with nobody reading the changelog,
  and the docs now say where channel content goes.
- **Repo governance (#154).** `SECURITY.md` says where to report and what the
  interesting surface is (the gate chain), and Dependabot is on.

## Upgrading

Pull **voitta-yolt**, **skillz** and **skillz-private** before this repo -- the
runtime reads all three.

    git pull
    .venv/bin/pip install -r requirements.txt
    .venv/bin/python selfcheck.py
    deploy/service.sh restart

Then the three items above: `allow_domains` in every channel policy, a
voitta-yolt in `>= 1.6.0, < 2.0.0`, and `logging.path` plus one `chmod 600` of
the existing log.
