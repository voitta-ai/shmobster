1"""Pending mutating commands, awaiting a human okay (#48). 

2 

3A command YOLT calls mutating is parked here with a short id instead of being 

4dropped on the floor; a trusted user then approves it by id (admin_tools 

5approve_command) and it runs. In-memory only: a restart clears the queue, which 

6is the safe direction -- a stale approval is worse than being asked again. 

7 

8This module is ingest-agnostic: it holds the queue, and each ingest renders its 

9own approval surface over it (Slack posts Approve/Deny buttons -- #50). 

10 

11An id is unique to this boot, not merely to this process's counter (#109). The 

12counter alone restarts at 1, while an approval card is a Slack message that 

13outlives the process and carries the id in its button value -- so after a 

14restart an old card could name whatever request was handed 1 the next time 

15round, and a human clicking Approve on what they read would release something 

16else. That is the one property the gate exists to provide, and neither the 

17channel scope nor the trust check catches it, since both are satisfied. So the 

18key is `<boot nonce>-<n>` with a nonce drawn fresh at every start: a card from a 

19previous boot matches nothing and is reported as no longer pending. 

20 

21The nonce is on the id every surface prints, not only on the value the button 

22carries. A stale card still shows its id, and typing that id is the documented 

23fallback for when the buttons are not available -- so a bare `<n>` completed 

24into "this boot's <n>" would walk straight back into the same failure by the 

25typed route, the human reading one command while another one runs. A bare number 

26therefore resolves to nothing: what a human types is the id exactly as the card 

27shows it. An id that resolves to nothing is answered with how many requests are 

28parked, never with which -- that answer goes back into the model's tool loop, 

29where a live id is an id it can approve without a human ever having quoted it. 

30 

31Every read and write of the queue is under one lock (#103). Bolt serves mention 

32handlers and button handlers on different threads, so surfacing cards, parking, 

33acquiring and popping all overlap; unsynchronized, the cheapest symptom is a 

34RuntimeError from iterating a dict another thread is mutating, and the most 

35expensive is an approved command that never runs. 

36 

37Approval answers *may this run at all*; the channel policy (policy.check) still 

38answers *is this in scope* at exec time. The two are separate gates. 

39 

40Park and claim are logged (#94). The queue lives only in this process, and the 

41approval card is the only other place a parked command is ever written down -- 

42so once that card is gone, the log is the sole surviving record of what was 

43asked for. Commands are logged as repr: a newline in one would otherwise forge 

44extra lines in a line-oriented log, in the very record this exists to trust. 

45 

46The command is scrubbed here, at the emission site, not left to the formatter 

47redact.install_logging() wraps. That formatter is installed by the Slack ingest 

48at import; this module is deliberately ingest-agnostic and reachable through 

49tools.run_shell from a script, a test, or the next ingest, none of which have 

50run that bootstrap. A log file is durable in a way an approval card is not, so 

51the one place that must not depend on who booted us is this one."""

61# Drawn fresh on every start and mixed into every id (#109). Nothing persists 

62# it, deliberately: the whole point is that a previous boot's ids resolve to 

63# nothing rather than to whatever has since reused their number. 

64# 

65# 64 bits, not the 32 that would also read as "random enough". A repeat is not a 

66# cosmetic clash here -- it is a card from a dead boot resolving to a live 

67# request again, which is the failure this exists to end, and it would be 

68# guarding a Slack message that can outlive many restarts. The cost of the extra 

69# bytes is eight more characters for whoever types an id by hand. 

70_NONCE = secrets.token_hex(8) 

71_MAX = 50 

72# Requests a surface has taken out of the queue and not yet finished or put 

73# back (#105). Ownership, not a flag: acquire() MOVES the request here, so 

74# there is exactly one transition and a second consumer -- another delivery of 

75# the same click, or a trusted user typing `approve <id>` mid-run -- can only 

76# ever be told "already in flight", never "no pending request" for a command 

77# that did run. 

78_INFLIGHT = {} # request id -> the request dict 

79_LOCK = threading.Lock()

82def canonical(key): 

83 """The queue key for an id arriving from anywhere: a button value, a human 

84 typing `approve [a1b2c3d4e5f60718-4]`, a model relaying either. 

85 

86 Normalization only, and only of what a human puts around an id they are 

87 copying: surrounding brackets, because every surface prints the id as 

88 `[<id>]` and quoting a card verbatim is the obvious thing to do; a leading 

89 `#`; stray whitespace. Deliberately not a place where a partial id is 

90 completed -- a bare number is not treated as this boot's, because the 

91 surface it was read off may be a card from a dead one, and expanding it here 

92 is exactly how the id a human read and the request that runs come apart 

93 again. Brackets around a bare number still leave a bare number.""" 

94 retval = str(key).strip().strip("[]").strip().lstrip("#").strip() 

95 return retval

110 key = f"{_NONCE}-{next(_ids)}" 

111 # Logged before the queue is touched, for the same reason pop logs before 

112 # the delete: scrub() is fail-closed, and a raise after the insert would 

113 # leave a request parked that no caller ever got an id for -- an orphan 

114 # nobody can approve, which is the shape of bug this all exists to fix. 

115 # The reason gets the same treatment as the command: yolt_gate renders its 

116 # own failures as "yolt error: <exc>", and a TimeoutExpired there carries 

117 # the classifier's argv -- which is the command, again, by another route. 

118 logging.info("approvals: parked [%s] in %s (%s): %s", key, channel, 

119 repr(redact.scrub(reason)), repr(redact.scrub(command))) 

120 with _LOCK: 

121 _PENDING[key] = { 

122 "command": command, "channel": channel, "reason": reason, "surfaced": False, 

123 # Whether the classifier refused outright rather than asked (#172). 

124 # Carried on the request because the card is rendered from it, and a 

125 # human clicking through a row of cards has no other way to tell the 

126 # two apart. The default under-warns rather than over-warns: a 

127 # caller that forgets it gets an ordinary card for a refusal, not a 

128 # refusal card for an ordinary park, which would cry wolf on every 

129 # queue. run_shell is the only caller; a second one must pass it. 

130 "refused": refused, 

131 # The thread this belongs to, recorded at PARK time (#266). 

132 # It used to be written only when the ingest surfaced the card, 

133 # on the argument that the queue is ingest-agnostic and the tool 

134 # loop had no thread. The loop has had one since #238, and the 

135 # deferral had a cost: a request parked AFTER a surfacing pass was 

136 # invisible to pending_in(), so begin_resume() let the turn 

137 # continue while that card was still waiting. Measured -- two 

138 # parked, one surfaced, pending_in answered 1. 

139 # 

140 # claim_unsurfaced() still writes it, for a caller that does not 

141 # pass one; the two must agree and it no longer overwrites. 

142 "thread_ts": thread_ts, 

143 # WHOSE task this is, as opposed to who approves it (#262). The 

144 # resumed turn is the answer to the original question, so it must 

145 # be written for the person who asked -- a designer's task approved 

146 # by an operator still reaches the designer, in the same thread. 

147 "requester": requester, 

148 # A structured call for a non-shell approval (#299). run_shell parks 

149 # a command string and run_approved executes it with tools.execute; 

150 # an MCP mutate parks this instead -- {"kind": "mcp", server, tool, 

151 # arguments, url, timeout} -- and run_approved routes on the kind. 

152 # Credentials are NOT here: only the server name, so headers are 

153 # re-read from the live policy at execution. 

154 "payload": payload, 

155 } 

156 # Overflow never evicts a held request (#103). acquire() leaves it in 

157 # the queue until the approve path pops it, so an oldest-first eviction 

158 # during that window turns a trusted click into "no pending request" 

159 # and the command a human approved simply never runs. 

160 # 

161 # Nor the request being parked right now, which is otherwise its own 

162 # victim once everything older is held: add() would hand back an id for 

163 # a request it had just deleted. When there is nothing evictable the cap

165 # going one over beats returning a dead id.

170 victim = next((k for k in _PENDING if k != key), None) 

171 if victim is None: 

172 break 

173 _forget_deferred(_PENDING.pop(victim)) 

174 retval = key 

175 return retval

178# Threads with a resume in flight (#169 review). Not a record of which threads 

179# have ever resumed -- a thread resumes once per round of parks, and there are 

180# many rounds. 

181_RESUMING = set() 

182# The latest outcome per thread that was refused a resume because other 

183# requests were still parked (#356). Normally the last of those resolving 

184# resumes the thread and this is simply dropped. It is kept for the one case 

185# where the last one never resolves by a human: its card is rejected and it is 

186# withdrawn, and without this nothing would ever carry the thread on. Bounded 

187# like the queue; the oldest thread's entry goes first. 

188_DEFERRED = {} # (channel, thread_ts) -> the resume() arguments 

189# Requests a surface has acquired and not yet released (#356 review). Not 

190# _INFLIGHT: finish() takes a request out of that BEFORE its command runs, so 

191# for the whole run nothing in the queue says the thread has a resolution 

192# coming. take_deferred() reads this so a withdrawal cannot resume the thread 

193# under a click that is still running -- that click resumes it when it is done. 

194_RESOLVING = {} # request id -> the request dict

197def _parked(channel, thread_ts, pool):

199 A request with no thread counts against every thread, as in pending_in().""" 

200 retval = any(req.get("channel") == channel and req.get("thread_ts") in (thread_ts, None) 

201 for req in pool) 

202 return retval

205def _forget_deferred(req): 

206 """A request left _PENDING by a route that is not withdraw(): drop the 

207 outcome kept for its thread if nothing there is parked any more (#356 

208 review). Caller holds _LOCK. 

209 

210 A typed approve or deny, and overflow eviction, take the last request out 

211 of a thread without going through begin_resume(), which used to be the only 

212 thing that dropped a kept outcome. It then survived into a later round of 

213 parks, and a withdrawal hours on resumed the thread from an approval that 

214 round had nothing to do with. withdraw() does not call this: it is the one 

215 exit that is meant to hand the outcome to take_deferred().""" 

216 channel, thread_ts = req.get("channel"), req.get("thread_ts") 

217 for key in [k for k in _DEFERRED if k[0] == channel and thread_ts in (k[1], None)]: 

218 if not _parked(key[0], key[1], _PENDING.values()): 

219 del _DEFERRED[key]

222def begin_resume(channel, thread_ts, outcome=None): 

223 """Claim the resume for this thread, or return False (#169 review). 

224 

225 pending_in() alone is not enough. Two clicks land on two Bolt worker 

226 threads; each pops its own request and runs it, and when both finish both 

227 see an empty queue for the thread -- so both resume, and one thread gets 

228 two turns arguing about the same outcome. The check and the claim have to 

229 happen under one lock, which is what this is. 

230 

231 `outcome`, when refused because the thread is still parked, is kept for 

232 take_deferred() (#356). A claim drops whatever was kept: the turn it 

233 starts reads the whole thread, so the deferred outcome is not lost, and 

234 keeping it would let a later withdrawal resume the thread a second time.""" 

235 key = (channel, thread_ts) 

236 with _LOCK: 

237 if key in _RESUMING: 

238 retval = False 

239 elif _parked(channel, thread_ts, _PENDING.values()): 

240 if outcome is not None: 

241 _DEFERRED.pop(key, None) 

242 _DEFERRED[key] = outcome 

243 while len(_DEFERRED) > _MAX: 

244 del _DEFERRED[next(iter(_DEFERRED))] 

245 retval = False 

246 else: 

247 _DEFERRED.pop(key, None) 

248 _RESUMING.add(key) 

249 retval = True 

250 return retval

253def take_deferred(channel, thread_ts): 

254 """The outcome a withdrawal should resume this thread with, or None (#356). 

255 

256 Only when nothing is parked in the thread any more and a human resolved a 

257 request whose resume was refused while it waited. A thread whose only 

258 request was withdrawn has nothing here and is not resumed: no human acted, 

259 and a turn started from a withdrawal would likely park the same command 

260 and meet the same rejected card. Taken under the lock with the parked 

261 check, so two withdrawals cannot both take it. 

262 

263 Not while a request in the thread is being resolved, either: that surface 

264 calls resume() when it is done, and resuming here first would leave its 

265 outcome to an "already resuming" refusal. The kept outcome stays; that 

266 claim drops it.""" 

267 key = (channel, thread_ts) 

268 with _LOCK: 

269 if (_parked(channel, thread_ts, _PENDING.values()) 

270 or _parked(channel, thread_ts, _RESOLVING.values())): 

271 retval = None 

272 else: 

273 retval = _DEFERRED.pop(key, None) 

274 return retval

295def pending_in(channel, thread_ts): 

296 """How many requests are still parked in this thread (#169). 

297 

298 A turn can park several commands, and each gets its own card. Resuming the 

299 turn on the first click would start a turn per click, in the same thread, 

300 each one seeing a different half of the outcome -- so the ingest asks this 

301 and resumes only when the answer is 0. A request being run right now is 

302 held, which means it is out of _PENDING entirely (#105) and correctly not 

303 counted here: the click that is resolving it is the one asking.""" 

304 with _LOCK: 

305 # A card with no thread counts against EVERY thread in the channel 

306 # (#266 review). It cannot happen from the Slack ingest -- `thread_ts` 

307 # is `event["thread_ts"] or event["ts"]`, and every message has a ts -- 

308 # but a future ingest (#25's email, say) that forgot to pass one would 

309 # otherwise park a card invisible to this count, and the turn would 

310 # resume while it waited. Blocking every thread is over-strict and 

311 # visible; being invisible is neither. 

312 retval = sum(1 for req in _PENDING.values() 

313 if req.get("channel") == channel 

314 and req.get("thread_ts") in (thread_ts, None)) 

315 return retval

318def claim_unsurfaced(channel, thread_ts=None): 

319 """Requests in this channel that no ingest has rendered yet, marked as 

320 surfaced so a second call (or a second reply in the same thread) doesn't 

321 post duplicate buttons. Returns [(id, request), ...]. 

322 

323 Locked like the rest: this runs on the mention thread while button handlers 

324 add and pop on theirs, and iterating _PENDING unsynchronized raises 

325 RuntimeError: dictionary changed size during iteration -- which would take 

326 out the reply that was about to show the buttons. The snapshot is built and 

327 marked under the lock, then posted outside it.""" 

328 out = [] 

329 with _LOCK: 

330 for key, req in list(_PENDING.items()): 

331 if req.get("channel") != channel or req.get("surfaced"): 

332 continue 

333 # Another thread's request is left for that thread's turn, which 

334 # surfaces what it parked when it ends, a failed turn included. 

335 # Taking it here posted a card into a conversation that never 

336 # asked for it: two turns ran at once in one channel, and the one 

337 # that finished first carried the other's cards off with it. 

338 if (thread_ts is not None and req.get("thread_ts") is not None 

339 and req["thread_ts"] != thread_ts): 

340 continue 

341 req["surfaced"] = True 

342 # Since #266 add() records the thread at park time, so this is the 

343 # fallback for a caller that did not pass one. 

344 if req.get("thread_ts") is None: 

345 req["thread_ts"] = thread_ts 

346 out.append((key, req)) 

347 retval = out 

348 return retval

351def unsurface(key): 

352 """The ingest could not post the card for a reason that may pass -- a rate 

353 limit, a Slack outage, the network (#129 review): make the request 

354 eligible for another one on the next mention, rather than pending with no 

355 surface and no id anyone was ever shown. A card Slack rejects outright is 

356 withdrawn instead (#356). 

357 

358 Returns how many times this request's card has now failed this way, or 0 

359 when it is no longer pending. Counted on the request, under the lock, so 

360 the ingest can stop retrying: Slack can answer some payloads with 

361 internal_error or a 5xx every time, and an endless retry is the same 

362 permanent thread hold that withdraw() exists to end (#356 review).""" 

363 with _LOCK: 

364 req = _PENDING.get(canonical(key)) 

365 if req is None: 

366 retval = 0 

367 else: 

368 req["surfaced"] = False 

369 req["card_failures"] = req.get("card_failures", 0) + 1 

370 retval = req["card_failures"] 

371 return retval

374def withdraw(key): 

375 """Slack rejected the card itself: drop the request unrun (#356). 

376 

377 unsurface() retries on the next mention, and a card Slack rejects is 

378 rejected the same way every time -- so the request stayed parked with no 

379 card and no id any human was shown. Nobody could approve or deny it, and 

380 since pending_in() and begin_resume() count it, every later approval in the 

381 thread resolved and then stopped, waiting on it. 

382 

383 Withdrawn is the direction the queue already takes on a restart: a request 

384 nobody can see is worse than being asked again. Only a pending request is 

385 withdrawn; a held one is being acted on by someone who quoted its id, and 

386 is left to that surface. Logged before the delete, like acquire(), so a 

387 fail-closed scrub leaves the request parked rather than gone unrecorded. 

388 Returns the request, or None when there was nothing to withdraw. Nothing 

389 here runs the command.""" 

390 with _LOCK: 

391 k = canonical(key) 

392 req = _PENDING.get(k) 

393 if req is None: 

394 retval = None 

395 else: 

396 logging.info("approvals: withdrew [%s] in %s, its card could not be posted: %s", 

397 k, req.get("channel"), repr(redact.scrub(req["command"]))) 

398 del _PENDING[k] 

399 retval = req 

400 return retval

403def pop(key, channel): 

404 """Claim and consume a request in one step: acquire() then finish(). 

405 

406 Returns None for a request that is held by another surface (#105) exactly 

407 as for one that is absent -- callers that need to tell those apart ask 

408 status(). Kept as the composite because "take it and run it" is still the 

409 common shape for a caller that owns no card.""" 

410 req = acquire(key, channel) 

411 if req is not None: 

412 finish(key) 

413 release(key) # a no-op on the queue after finish(); ends the resolving mark 

414 retval = req 

415 return retval

418def acquire(key, channel): 

419 """Take ownership of a request, or return None. 

420 

421 The request MOVES out of _PENDING (#105): while a surface holds it, no 

422 other consumer can pop it, approve it by text, or evict it on overflow -- 

423 they see "held", not "gone", and the log cannot end up with one surface 

424 saying the command ran while another says there was nothing to run. That 

425 was #103's hold made advisory; this is it made authoritative. 

426 

427 The caller owes exactly one of finish() -- the request is consumed, on the 

428 same pop-before-execute rule as before -- or release(), which puts it back 

429 pending, the retryable direction. release() after finish() is a no-op, so 

430 a finally: release() around a body that finishes on success is correct. 

431 

432 Logged here as the claim: this is now the moment a request leaves the 

433 queue, and the log's job is to record that exactly once (#94). Logged 

434 before the move for the reason the old pop() logged before its delete: 

435 scrub() is fail-closed, and failing here leaves the request parked.""" 

436 with _LOCK: 

437 k = canonical(key) 

438 req = _PENDING.get(k) 

439 if req is None or req.get("channel") != channel or k in _INFLIGHT: 

440 retval = None 

441 else: 

442 logging.info("approvals: claimed [%s] in %s: %s", k, channel, repr(redact.scrub(req["command"]))) 

443 del _PENDING[k] 

444 _INFLIGHT[k] = req 

445 _RESOLVING[k] = req 

446 _forget_deferred(req) 

447 retval = req 

448 return retval

458def status(key, channel): 

459 """One locked snapshot of a request: ("held"|"pending"|"absent", req|None). 

460 

461 Read in a single acquisition rather than peek() and then held(), so a 

462 surface can never render a state that never existed -- pending according to 

463 one call and not held according to the next, because a click landed in 

464 between. It can still go stale on the way to Slack; nothing about a live 

465 queue is instantaneously true. What it must not be is self-contradictory. 

466 

467 "held" is asked first because a held request lives in _INFLIGHT, not 

468 _PENDING (#105), for the whole duration of the run. Unlike before, "held" 

469 now comes WITH the request, so a surface that must name the command -- a 

470 refused click during a run (#94) -- can. Channel-scoped throughout: an id 

471 is unique per boot (#109), so the scope is no longer what keeps two 

472 channels' requests apart -- it is the separate guarantee that an approval 

473 raised in one channel is answerable only there (#107). 

474 """ 

475 with _LOCK: 

476 k = canonical(key) 

477 held = _INFLIGHT.get(k) 

478 if held is not None and held.get("channel") == channel: 

479 retval = ("held", held) 

480 return retval 

481 req = _PENDING.get(k) 

482 if req is not None and req.get("channel") != channel: 

483 req = None 

484 if req is not None: 

485 retval = ("pending", req) 

486 else: 

487 retval = ("absent", None) 

488 return retval

492 """Put a held request back in the queue -- the surface could not or did 

493 not act on it. No-op on the queue after finish() and for a key never

495 request's resolving mark (#356 review). `surfaced` is left as it was: the card

501 if req is not None: 

502 _PENDING[k] = req
